# Problem-Solving Growth

Before the training, complex technical problems could appear difficult because several systems were involved at the same time.

During the training, I learned to break problems into smaller parts.

My debugging approach became:

1. Identify the exact error.
2. Find which component is affected.
3. Check the relevant file.
4. Test a small change.
5. Validate the result.
6. Continue only after the previous part works.

This approach helped during frontend, backend, Docker and Git troubleshooting.

# Challenges Faced

## 1. Full-Stack Integration

### Challenge

Multiple parts of the project had to work together.

### Solution

Separate the application into frontend, backend, AI, mobile and DevOps areas.

---

## 2. Docker Configuration

### Challenge

Frontend and backend services needed to run together.

### Solution

Created separate Dockerfiles and a Docker Compose configuration.

---

## 3. Backend Port Conflict

### Challenge

Port 5000 was already being used during Docker startup.

### Solution

The existing process was identified and stopped before starting the Docker backend container.

---

## 4. Git Delivery

### Challenge

Day 27 required multiple new project files and a feature branch.

### Solution

The project was validated, committed and pushed using Git.

# Lessons Learned

## Foundation First

Strong fundamentals make advanced technologies easier to understand.

## Learn by Building

Practical implementation provides better understanding than theory alone.

## Debug Systematically

Errors become easier to solve when they are isolated and tested one at a time.

## Documentation Matters

A project is easier to understand when its architecture and usage are documented.

## Security Matters

Sensitive configuration should not be placed directly in source code.

## Validation Matters

A project should be tested before it is presented or delivered.
